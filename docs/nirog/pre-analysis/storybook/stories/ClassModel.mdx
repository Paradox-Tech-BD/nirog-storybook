# Application Class Model

This is the merged class model created from the original Nirog UML classes and the backend evidence, catalog, regimen, and sync requirements. It retains the user-facing concepts—users, preferences, profiles, medicine, OCR scan, reminders, dose logs, refill data, notifications, and adherence statistics—while refining their ownership boundaries.

<MermaidDiagram title="Complete Nirog application class model" chart={applicationModel} />

## Merge decisions

The original `Medicine` class becomes two concepts: `MedicineProduct` is shared released catalog data, while `MedicationRegimen` is the profile-private medication course. The original `OCRScan` is part of a three-stage boundary: `PrescriptionDocument` preserves the source, `OCRScan` stores ML processing, and `MedicationReview` stores the user decision. A `RegimenVersion` prevents instruction edits from changing historical dose records.
