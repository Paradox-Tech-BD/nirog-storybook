# Evidence and ML Data Lifecycle

The evidence lifecycle preserves an original document asset, derived transforms, stage manifests, model/provider/prompt/release inputs, extracted observations, matching candidates, and a review payload. It produces evidence states such as `ready_for_review`, `review_required`, and `manual_entry_recommended`; it never produces `active_regimen`.

<MermaidDiagram title="Restricted evidence lifecycle" chart={evidenceState} />

Every stage run is lineage-bound to its material inputs. Changed preprocessing, model, parsing schema, catalog release, or policy creates a new lineage; repeated mobile submissions are controlled separately through idempotency. Provider uncertainty is reconciled by deterministic request key before any safe reattempt.

Read [Evidence and ML Data Lifecycle](https://github.com/Paradox-Tech-BD/nirog-storybook/blob/main/docs/nirog/data-management/04-evidence-and-ml-data-lifecycle.md).
