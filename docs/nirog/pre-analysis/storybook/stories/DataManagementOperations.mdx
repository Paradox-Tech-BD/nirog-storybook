# Retention, Recovery, and Operability

Every Nirog data product has a declared purpose, retention trigger, hold rule, purge method, backup interaction, and recovery owner. A retention job only completes after the database state, private-object lifecycle, indexes/caches, queued work, and audit evidence reconcile.

<MermaidDiagram title="Governed retention and purge lifecycle" chart={retentionLifecycle} />

Recovery is source-aware. A database restore triggers outbox/provider-intent reconciliation; an index is rebuilt from immutable release manifests; a sync defect repairs projections rather than rewriting canonical actions; and an exposure investigation revokes scoped access while preserving minimized audit evidence.
