# Data Management Overview

Nirog’s Data Management section is a dedicated approach to **ownership, purpose, classification, lineage, access, lifecycle, recovery, and safe change**. It does not repeat the generic reference schema example: it is designed around profile-scoped medication data, restricted prescription evidence, user-confirmed regimens, immutable catalog releases, and a Flutter synchronized view that is never the clinical system of record.

<MermaidDiagram title="Nirog’s data planes" chart={dataPlane} />

## The organizing distinctions

**Evidence versus action.** Model output is reviewable evidence; only an authorized confirmation command can create a regimen version.

**Private versus shared.** Profile health and evidence data does not passively modify catalog reference data. Shared change requires curation and a published release.

**Authoritative versus derived.** Regimens, dose events, evidence manifests, releases, and audit/control records are authoritative. Schedules, summaries, indexes, caches, and sync views are rebuildable derivatives.

**Provenance versus audit.** Provenance explains creation and revision; audit records access and policy/action decisions.
