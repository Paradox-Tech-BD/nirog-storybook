# Access, Consent, and Privacy

Profile access is current evaluated policy, not a permanent boolean. The backend validates account identity, profile relationship/grant, consent/purpose, requested action, target resource, and relevant time/device state before establishing a scoped request capability. Repository filtering and PostgreSQL RLS then provide layered protection for the owned data operation.

<MermaidDiagram title="Current policy evaluation before profile data use" chart={accessDecision} />

Restricted evidence is stored privately and travels by narrow reference/grant, never through generic queue payloads, client sync, public links, or traces. Revocation, account deactivation, device removal, and retention/purge state are rechecked at sensitive worker boundaries as well as API boundaries.

Read [Access, Consent, and Privacy Data Controls](https://github.com/Paradox-Tech-BD/nirog-storybook/blob/main/docs/nirog/data-management/03-access-consent-and-privacy.md).
