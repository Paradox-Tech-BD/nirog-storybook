# Staged Environment Execution

The environment is assembled in **dependency order**. Each stage leaves a runnable system with its own tests and acceptance gate. Authorization, audit, event delivery, and AI accounting are foundational controls, not late-stage features.

<MermaidDiagram title="Nirog staged implementation path" chart={execution} />

## First code milestone

The first implementation slice stops before business endpoints. It creates the private workspace, Docker Compose, typed configuration, Fastify health endpoints, safe problems, OpenAPI/Scalar, Drizzle migration pipeline, PostgreSQL roles, RLS test fixture, audit/outbox/idempotency/consumer-ledger tables, and architecture/integration test harnesses.

No patient route, real OIDC credential, AI provider call, Strapi handoff, or OCR integration enters the first slice. Those workflows are only introduced with their exact data authority, command contract, safety checks, and tests.

## Delivery gates

Every database change includes migration rehearsal and RLS tests. Every API change includes an OpenAPI diff and Flutter compatibility statement. Every worker change includes duplicate, timeout, retry, and evidence-only-output tests. Every AI operation includes a quota reservation/settlement ledger trail. Every Strapi change includes a signed handoff and immutable Core release test.
