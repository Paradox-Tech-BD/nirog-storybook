# Phase 9 Reconciliation and Reminder Timeline

The Core continuation has been reconciled through commit `63c8c6b`. It already includes persisted adherence reporting, reminder due-intent dispatch, snooze and acknowledgement, inventory movement history, refill-alert acknowledgement, and the review-gated OCR provenance/receipt workflow. The reconciliation did not reimplement those slices.

The additive Core release introduces the missing patient-facing occurrence timeline: a bounded, profile-authorized route that returns the concrete reminder occurrence ID, scheduled instant, delivery window, and workflow state required to use the existing snooze and acknowledgement actions.

## Endpoint contract

`GET /api/v1/profiles/{profileId}/regimens/{regimenId}/reminder-occurrences` requires the existing `notification.manage` profile capability. It accepts `from`, `to`, and an optional `limit`; the interval is start-inclusive and end-exclusive, must be no more than 31 days, and defaults to 50 results with a maximum of 100.

The response uses the standard Core success envelope. It exposes identifiers, `scheduledFor`, `windowOpensAt`, `windowClosesAt`, state, and only applicable state-transition timestamps. It excludes notification text, dosage, device token, OCR text, signed URLs, and provider credentials.

## Safety position

An occurrence remains a workflow record. A read, delivery intent, snooze, or acknowledgement never creates a dose log, modifies inventory, changes a prescription, or claims medication was taken. The provider adapter remains intentionally separate: the dispatcher emits only identifier-only due intents until a future provider-specific and credential-sealed delivery increment is approved.
