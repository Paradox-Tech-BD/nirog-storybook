# Backend Filesystem

The new private **`nirog-core`** repository is a pnpm workspace and a modular monolith. It creates one shared contract and quality boundary while separating executable responsibilities: API, migrator, dispatcher, and Python worker images.

<MermaidDiagram title="Nirog backend workspace" chart={workspace} />

## Module discipline

Every business module has `domain`, `application`, `infrastructure`, and `http` areas. HTTP converts a validated request into a typed command. The application handler owns authorization, state checks, idempotency, transaction, audit, and outbox. Infrastructure implements ports; domain logic imports neither Fastify nor Drizzle.

**Typed contracts are central.** `packages/contracts` owns versioned public API shapes, events, and restricted internal commands. Consumers never deserialize a producer’s tables directly.

**Workload identity is separate.** The dispatcher claims outbox leases and invokes only explicitly registered handlers; it cannot run clinical commands. The migrator owns DDL but serves no HTTP traffic. Python workers do not receive direct clinical database credentials.

**Strapi stays out of this workspace.** Its independent Yarn/Strapi lifecycle lives in a separate private `nirog-strapi-admin` repository and communicates only through a signed release handoff.
