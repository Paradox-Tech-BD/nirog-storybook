# Access, ML, Flutter, and Contract Stack

The stack separates **authentication**, **profile authorization**, **evidence processing**, and **mobile synchronization**. A generic OIDC adapter verifies identity, while Nirog retains profile grants, consent, persisted permission snapshots, resource relationships, and audit in PostgreSQL. RBAC is active now; a typed policy-evaluator interface enables future PBAC without replacing grants.

## Integration rules

**Access.** The OIDC verifier emits a minimal immutable actor. The Profile Policy Service evaluates the live profile relationship, persisted permission set, relation fact, and consent/purpose before creating a request-local capability.

**OCR and ML.** PaddleOCR plus ONNX Runtime is the self-hosted worker baseline behind `PrescriptionOcrPort`. Managed providers remain optional adapters and must meet release, evaluation, residency, redaction, timeout, purge, and deterministic-key controls before use.

**Flutter.** OpenAPI 3.1 is exported from FastAPI, linted with Redocly, and used to generate a Dart/Dio client. Flutter persists intents locally, provides idempotency and expected version, and renders server-authoritative change feeds. It never decides clinical state or authorization.
