# Backend, Data, and Async Runtime

The backend uses **FastAPI with strict Pydantic v2 request and response models**, immutable application commands, domain values, and explicit repository/port interfaces. SQLAlchemy 2 with `asyncpg` implements persistence without exposing ORM entities outside infrastructure adapters. Alembic is the only production schema-change tool.

<MermaidDiagram title="Nirog command, transaction, and worker runtime" chart={runtimeMap} />

## Runtime rules

**Typed command boundary.** Routes parse untrusted payloads, resolve an immutable actor and profile capability, and call one application command. The handler controls validation, transaction, domain state transition, audit, idempotency, outbox, and response receipt.

**PostgreSQL authority.** Use one PostgreSQL 18 cluster with module schemas, database roles, constraints, transaction-local profile scope, and RLS as defense in depth. API and worker runtime roles must not own tables or have `BYPASSRLS`.

**Queue-specific execution.** Celery 5.6 uses distinct ML, catalog, projection, notification, and maintenance queues. Tasks carry references and fingerprints only, re-check lifecycle state before work, apply idempotently, and observe timeouts, backoff, dead-letter, and reconciliation policy.
