# Implementation Start Plan

Implementation begins by proving safety infrastructure before high-variance workflow automation. The first repository includes `pyproject.toml`, `uv.lock`, Docker and Compose files, OpenTofu infrastructure, GitHub Actions, OpenAPI governance, and the Nirog modular source layout. Empty future-module scaffolds are not required.

<MermaidDiagram title="Nirog implementation milestones" chart={startMap} />

## First safe milestone

The first working increment delivers settings, dependency injection, typed IDs and safe errors, migration harness, database roles and RLS fixture, OIDC actor mapping, profile capability, audit/idempotency/outbox primitives, correlation logging, OpenAPI export/lint, container build, and CI policy. It must prove BOLA resistance, RLS reset, audit redaction, transaction/outbox atomicity, and safe errors before additional domain endpoints are added.

## Ordered expansion

Build identity and catalog next, then the restricted evidence boundary, user-confirmed regimen and adherence commands, mobile/notification synchronization, and finally ML quality plus operational maturity. Each milestone contains its own required test evidence, release safety, and rollback/recovery criteria.
