# ML Integration Pre-Analysis

Two supplied Notion design pages now inform the Nirog general pre-analysis: the product page and its detailed AI/ML pipeline proposal. Together, they support handwriting recognition, organized text, medicine-catalog retrieval, confidence-aware suggestions, feedback, and asynchronous progress—but they do not replace Nirog’s evidence-preserving and user-confirmed medication boundary.

<MermaidDiagram title="ML integration product boundary" chart={mlIntegrationBoundary} />

## What this pre-analysis accepts

The product may take a photo or gallery image, hash it for deduplication, preserve it as restricted source evidence, produce traceable derived preprocessing artifacts, run recognition and extraction, retrieve catalog candidates, and use calibrated signals to route the result to a review screen. It can use private feedback and carefully curated shared catalog changes to improve retrieval over time.

## What it does not allow

An OCR result, semantic retrieval hit, high-confidence candidate, or automated “match” does not create an active medication plan. Only an authorised review decision can create or update a versioned profile-private regimen. User-created names remain private until a separate curation and publication flow makes a shared catalog change.

## What remains deferred

This is still pre-analysis. Model provider, fallback composition, worker queue, vector store, embeddings, exact thresholds, storage service, real-time transport, and evaluation release gates will be selected only during technical analysis after product-owner authorization.
