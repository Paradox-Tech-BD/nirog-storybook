# Prescription and ML Evidence

This subsystem owns the original document, the asynchronous scan job, OCR evidence, extracted fields, candidate matches, and review decisions. It is deliberately separate from a medication regimen: the model may assist with extraction, but it never activates a schedule by itself.

## Review outcomes

The scan policy returns one of four outcomes. `ready_for_review` means the app can show a preselected candidate. `review_required` means medication-critical fields need confirmation. `manual_entry_recommended` means the image or matching evidence is insufficient. `failed` means a technical processing issue occurred. None of these outcomes is a clinical judgment.

## Release provenance

Every scan records the preprocessor release, vision model release, extraction schema version, abbreviation release, catalog release, index release, and matching-policy release. This makes each result reproducible when the ML service or catalog evolves.
