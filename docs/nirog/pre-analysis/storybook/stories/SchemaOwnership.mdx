# Schema Ownership

The ER diagram shows the cross-subsystem relationship IDs. Ownership is still explicit: the table that stores a relationship is written only by its owning module.

<MermaidDiagram title="Nirog schema ownership ER diagram" chart={ownershipER} />

## Database schemas

**identity** owns users, providers, preferences, devices, profiles, teams, invitations, access grants, and consent. **catalog** owns sources, releases, products, ingredients, aliases, and match indexes. **prescription** owns assets, documents, pages, scans, OCR output, extraction fields, candidates, and reviews. **regimen** owns private medication courses, instruction versions, schedule rules, planned doses, inventory, and refill rules. **adherence** owns reminder delivery, notifications, dose logs, refill history, alerts, and adherence projections. **platform** owns idempotent commands, change events, audits, provenance, purge jobs, and outbox events.

## Data visibility

Catalog products are shared reference data. Regimens, source images, OCR text, dose logs, and notifications are profile-private health data. A consumer never receives an object-storage permanent URL, raw auth credential, or data belonging to a profile outside its effective access grant.
