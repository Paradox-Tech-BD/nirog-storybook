# Access Control Enforcement

Authorization is evaluated server-side for every protected API request and restricted worker action. OIDC validates identity; the profile policy service evaluates current owner/grant, persisted permission snapshot, consent/purpose, target relationship, and trusted context; module repositories add a profile scope; PostgreSQL RLS supplies a second row-level barrier.

<MermaidDiagram title="OIDC-to-capability authorization chain" chart={authorizationChain} />

This layered sequence prevents broken object-level authorization: a valid permission for profile A does not allow a guessed document, regimen, or occurrence ID from profile B. In sensitive flows, an inaccessible target is indistinguishable from absence to the caller, while an internal redacted event retains the correlation and safe reason code for investigation.

At the **route dependency**, Nirog establishes token validity and the typed action/resource declaration. The **profile policy service** resolves the current owner/grant, permission snapshot, consent/purpose, and resource scope. The **owner service and repository** prove the exact target-to-profile relationship through scoped SQL, while **PostgreSQL RLS** provides defensive row filtering under transaction-local actor/profile context. **Object storage and workers** use short-lived, purpose-bound capabilities and narrow workload identities.
