# Event, Worker, and Consistency Architecture

Nirog is strongly consistent inside an owner command transaction and deliberately eventually consistent for derived projections/external effects. The outbox prevents lost dual writes; delivery can repeat. Consumers claim `platform.consumer_ledger`, verify fresh source state, and commit one owned effect, durable retry, safe no-op, reconciliation request, or recovery record.

<MermaidDiagram title="Committed event through idempotent worker recovery" chart={asyncFlow} />

The broker is never authoritative. External provider uncertainty is reconciled with a deterministic intent/key before resend. Dead-letter recovery starts a new attempt from authoritative current state; it never blindly republishes an old sensitive message.
