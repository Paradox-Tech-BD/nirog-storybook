# Canonical Data, Schema, and Provenance

PostgreSQL holds canonical transactional state and durable control records. Private object storage holds restricted binary/text artifacts by manifest reference. Catalog releases, evidence/manifests, review decisions, regimen versions, dose events, audit, and provenance preserve historical meaning. Search indexes, cache, future occurrence projection, summaries, and provider-delivery views are rebuildable and never become medication authority.

<MermaidDiagram title="Canonical module schemas, provenance, and derived data boundaries" chart={dataMap} />

The reconciliation establishes current physical targets such as `identity.accounts`, `catalog.releases`, `prescription.scan_jobs`, `regimen.regimens`, `adherence.dose_events`, and `platform.outbox_events`. `profile_id` narrows data ownership but never authorizes a request without current capability, repository scope, and RLS.
