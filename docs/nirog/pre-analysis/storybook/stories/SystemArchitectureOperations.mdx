# Operations, Recovery, and Evolution Architecture

Observability links API command, outbox event, worker attempt, provider operation, review payload, regimen action, and recovery case through correlation/causation context. It records redacted operational facts rather than raw prescription data. Changes use expand → compatible deploy → bounded idempotent backfill → validation → activation → observation → contract.

<MermaidDiagram title="Controlled change, incident, reconciliation, and recovery loop" chart={operationsFlow} />

Restore begins in isolation. PostgreSQL canonical records recover first; restricted assets follow manifest/lifecycle rules; outbox/ledger/provider intents, access/lifecycle states, indexes, summaries, and future projections reconcile before normal access resumes. Module extraction remains an evidence-led future decision, not a current deployment requirement.
