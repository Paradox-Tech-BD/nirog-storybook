# Unified System Architecture Overview

This parent area is the **single cross-cutting architecture reference** for Nirog. It connects the settled product boundary, physical schemas, FastAPI modules, Flutter/API contract, ML evidence pipeline, worker consistency model, security, data lifecycle, and operations. It was written after a reconciliation pass across the previous documentation roots.

## Reconciled system rules

**Account identity is not profile authority.** The API uses OIDC mapping, a current profile capability, repository scope, and RLS as complementary controls.

**ML evidence is not medication action.** Worker role constraints and immutable review payloads preserve the boundary; an authorized Regimen command is required for medication state.

**The database is authoritative while delivery is at least once.** Aggregate, audit, idempotency, and outbox records commit together; consumers use a ledger and current-state rechecks.

**Catalog facts and personal medication are distinct.** Catalog releases are immutable and shared, whereas regimen and version records are profile-private.

**Reminder delivery is not dose evidence.** Notification delivery telemetry remains separate from append-only dose events.
