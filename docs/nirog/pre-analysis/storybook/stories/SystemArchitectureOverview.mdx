# Unified System Architecture Overview

This parent area is the **single cross-cutting architecture reference** for Nirog. It connects the settled product boundary, physical schemas, FastAPI modules, Flutter/API contract, ML evidence pipeline, worker consistency model, security, data lifecycle, and operations. It was written after a reconciliation pass across the previous documentation roots.

<MermaidDiagram title="Nirog unified backend architecture" chart={unifiedMap} />

| Reconciled system rule | Architecture enforcement |
|---|---|
| Account identity is not profile authority. | OIDC mapping, current profile capability, repository scope, and RLS. |
| ML evidence is not medication action. | Worker role constraints, immutable review payload, authorized Regimen command. |
| Database is authoritative; delivery is at least once. | Aggregate/audit/idempotency/outbox commit, consumer ledger, current-state recheck. |
| Catalog facts and personal medication are distinct. | Immutable release-bound catalog versus profile-private regimen/version records. |
| Reminder delivery is not dose evidence. | Separate notification delivery telemetry and append-only dose events. |
