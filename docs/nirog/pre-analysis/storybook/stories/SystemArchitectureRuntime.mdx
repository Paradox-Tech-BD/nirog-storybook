# Runtime, Process, and Deployment Topology

Nirog starts as a modular monolith with separate API, relay, and worker processes—not separately owned microservices. All business modules share one authoritative PostgreSQL cluster and module contracts, while dedicated pools isolate expensive ML, catalog, notification, projection, and maintenance work from user-facing API capacity.

<MermaidDiagram title="One authoritative database with independently scaled process classes" chart={runtimeMap} />

API replicas own validated synchronous commands and never wait for model inference, import/index build, or push-provider completion. Workers use scoped identities and module services; they do not become a parallel policy layer. Redis-compatible infrastructure supports broker/cache functions but is not authoritative medication, authorization, or evidence state.
