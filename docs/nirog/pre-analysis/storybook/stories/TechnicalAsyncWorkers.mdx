# Asynchronous Workers and Reliability

Nirog uses dedicated queues for ML stages, catalog import/indexing, notifications, schedule/adherence projections, sync compaction, evaluation, and retention maintenance. The API does not wait for any of these workloads.

<MermaidDiagram title="Transactional outbox and idempotent consumer flow" chart={outboxFlow} />

## Reliability rules

Every committed domain change writes an outbox event in the same transaction. The relay may publish duplicates, so each consumer uses a ledger keyed by consumer and event ID. Retryable failures apply bounded backoff and jitter; permanent failures do not loop. Each queue has a DLQ with redacted diagnostics and an operator recovery path.

Dedicated worker pools keep long-running ML work from starving notifications, schedule projection, or mobile synchronization.
