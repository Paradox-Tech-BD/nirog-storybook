# Outbox and Worker State Migrations

This migration plan defines an ordered, backward-compatible PostgreSQL rollout for the reliable asynchronous platform. It starts with role separation and an additive transactional outbox, then adds consumer-ledger retry/lease state, deterministic provider intent, durable DLQ/recovery records, and reconciliation jobs before progressively enabling relay and consumer queues.

The rollout uses expand → deploy compatible code → activate/backfill → contract. It deliberately avoids treating broker messages as authoritative state and prevents stale queue payloads from bypassing current permission, release, cancellation, or aggregate-version checks.
