# Technical Architecture Overview

The full backend technical analysis is now organized into separate, implementation-oriented documents. Nirog begins as a **modular monolith** with a synchronous FastAPI command/query core, PostgreSQL as authoritative state, restricted object storage for evidence, and separately routed worker pools for asynchronous work.

<MermaidDiagram title="Whole backend recommended runtime shape" chart={backendArchitecture} />

## What changes from pre-analysis

Pre-analysis defined boundaries. Technical analysis turns them into module ownership, schema families, APIs, transaction behavior, outbox events, worker queues, authorization enforcement, release artifacts, and tests. The system remains logically decomposed while avoiding premature microservice operational cost.
