# Technical User Management

User Management owns account identity, OIDC identity mapping, patient profiles, caregiver grants, consent, preferences, devices, invitations, and profile authorization. It is deliberately separate from all health-content modules.

<MermaidDiagram title="Every profile-scoped action uses an evaluated capability" chart={profileAuthorization} />

## Enforced design decisions

An access token identifies the account but does not directly grant a patient profile. The server evaluates profile ownership or an active caregiver grant for every requested object. `profile_access` is the only durable profile-sharing authority; team membership alone cannot expose patient data.

Mutations require an idempotency key and aggregate version. The module writes the permission change, audit event, outbox event, and sync change in one transaction. PostgreSQL RLS is a second control for sensitive profile tables, not a replacement for route and policy checks.
