# Committed Effects, Retry, DLQ, and Reconciliation

Nirog treats the database as authoritative and queue delivery as at-least-once. The original command commits business state, audit, idempotency outcome, and outbox event together. Consumers claim a ledger lease, re-read current state, and then complete one owned effect or a durable safe no-op before acknowledging delivery.

<MermaidDiagram title="Reliable deferred-effect and recovery workflow" chart={recoveryFlow} />

Retries are bounded and only for temporary still-relevant work. A provider request with an unknown outcome is reconciled by deterministic intent/key before any resend. A dead-letter entry is a redacted operator workflow that reconstructs a fresh current-state attempt; it never blindly republishes an old payload.
