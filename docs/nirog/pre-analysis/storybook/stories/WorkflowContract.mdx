# Workflow Contract and State Vocabulary

Nirog distinguishes **definitions** (versioned policy/configuration), **requests** (governed intent), **canonical actions/events** (durable business facts), **evidence** (observations), and **derived effects** (rebuildable/deferred results). The distinction prevents “request accepted,” “provider notified,” “review ready,” and “medication active” from being treated as the same status.

<MermaidDiagram title="Universal Nirog workflow shape" chart={contractFlow} />

Every workflow must handle accepted, duplicate, stale, denied, cancelled, superseded, retrying, terminal failure, and recovery states. The safety-critical rule is that worker messages carry minimal references; workers re-read source, policy, version, cancellation, and retention state before effect commit.
