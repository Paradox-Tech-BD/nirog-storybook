# Release, Migration, Incident, and Recovery

Change to schemas, event contracts, catalog releases, ML configurations, policies, indexes, or retention is a workflow with explicit owner, compatibility, rollout, observability, and recovery evidence. Nirog uses expand → compatible deploy → bounded idempotent backfill → validation → controlled activation → observation → contract, with rollback/compensation where guardrails fail.

<MermaidDiagram title="Controlled change and incident recovery loop" chart={changeRecovery} />

Incident response contains affected work, preserves redacted audit/control evidence, inspects canonical state/outbox/ledger/provider intent, reconciles uncertainty, rebuilds only derived artifacts, and verifies invariants before controlled resume. Status communication never converts an outage into medication advice or infers dose behavior.
