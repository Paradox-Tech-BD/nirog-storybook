# Workflow Library Overview

The **Design Workflows** library consolidates Nirog’s previously distributed backend decisions into detailed, stateful, implementation-ready flows. Every workflow declares its trigger, actor/profile scope, authoritative owner, synchronous transaction, deferred event, safety gate, failure policy, and terminal state.

<MermaidDiagram title="Nirog workflow families and their core relationships" chart={workflowMap} />

| Workflow sequence | Design outcome |
|---|---|
| Identity → Evidence | An authenticated account still needs current profile capability and purpose before a private document can be processed. |
| Catalog + Evidence → Regimen | Catalog matching supplies release-bound candidates; it never activates medication. Evidence requires an explicit, authorized confirmation before a regimen version exists. |
| Regimen ↔ Flutter | Flutter sends idempotent user intent and receives an authorized change feed; it is not the clinical system of record. |
| Async + Privacy + Operations | Workers use committed events, current-state rechecks, retry/reconciliation, lifecycle controls, and recovery operations. |
